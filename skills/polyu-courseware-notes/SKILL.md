# PolyU 课程课件整理（polyu-courseware-notes）

> **关于本 skill**：由一名 PolyU 学生的真实工作流沉淀而成。下文出现的课程代码（QRST7890／ABCD1234／EFGH5678／IJKL9012／MNOP3456）**仅作案例举例，可整体替换为你自己的课程代码**；`§` 编号与课程代码配套出现，改动时一并调整。
> **工作区**：默认 `~/PolyU`，可用环境变量 `POLYU_HOME` 指定。


> 适用工作区：`~/PolyU`（个人的课程材料库）。
> 语言默认：中文为主（说明/汇总类），课程知识笔记英文为主 + 生僻词中文括注。
> 场景：用户下载新课件放入根目录或 Downloads 后说「继续整理」，或在已有笔记上要求更新/拆分/导出 Word。

## 一、输出布局（硬规则）

1. **每门课一个文件夹**（如 `ABCD1234_Policy_Research_Method/`），原始课件/大纲按原名归档进去；同名 `.pptx`（可编辑源）与 `.pdf`（导出）可同时保留。课件出新版本时保留旧版并改名标注（如 `… (v1, 日期, 独有内容说明).pdf`），避免丢失旧版独有页（评分细则等）。
2. **复习笔记 = 两种形态，职责分离**：
   - `复习笔记.md` —— **全课程可维护总源**：含课程结构/考核/GenAI 等课程级小节 + 各讲知识点小节（按讲顺序递增编号，如 `## 4. Lecture 1 — …`、`## 5. Lecture 2 — …`）。
   - `<课程代码>_复习笔记-第N讲.docx` —— **成品，一讲一个文件**。**严禁**把所有讲（或把多讲新增内容）合并进单个 `复习笔记.docx`/一个长文档。已有合并文件需拆掉。
3. 新讲到达时的固定动作：在 `复习笔记.md` 追加该讲小节 → 重新生成**该讲**的 docx（见 §五），不去动其他讲的 docx。
4. 课程级信息（考核构成/DDL/出勤/GenAI 红线/教师信息/上课时间地点）**不进复习笔记 docx**，放在课程 `README.md` 与根目录各汇总文件（`DDL汇总.md`、`出勤规定汇总.md`、`AI使用红线速查.md`、`README.md`、`课程总览.docx`、`会话交接快照.md`）。
5. 文件名约定：
   - 复习笔记成品：`<课程代码>_复习笔记-第N讲.docx`（N 为课件讲号，中文「讲」与 "Lecture" 等价）。
   - 原始课件：保留下载原名，不翻译、不改扩展名。
   - 各课程 README 内「文件夹内容」清单须与实际文件一一对应。
6. **工作区边界：只在 `~/PolyU` 内读写（实践确定的边界规则）**：
   - **禁止**扫描 `~/Downloads` 根目录、`~` 家目录或其他工作区外路径来"找新文件"，即使只是列目录看文件名。
   - 用户说"放了新文件/新课件"时，**只在工作区内查找**（`PolyU/` 根目录与各课程文件夹）；**若未找到，先问用户要路径，或请其把文件移进 `PolyU`**，不要自行到工作区外搜索。
   - 背景：`workspace-write` 策略只拦"修改"、不拦"读取"（实测：工作区外 `touch` 返回 `Operation not permitted`，但工作区外读取正常），因此必须靠自觉遵守，而不能指望沙箱兜底。
   - 例外：仅当用户**明确要求**查看某个工作区外路径时才读，且只读用户指定的那一个文件/目录，不扩散扫描。

## 二、笔记写作约定

1. 语言：知识性内容**英文为主**，仅在生僻/专有概念后加中文括注（如 `dependent development（依附性发展）`）；说明性汇总中文为主、关键句附英文。
2. 标记纪律：**不标「必考」**（课件未明说）；可依课件强度用 `★`（重点）/`★★`（核心，自行判断）；GenAI/引用相关标「重点关注」；课件写明「quiz 覆盖周次」的标可考提示。
3. 忠实来源：改写课件原文，关键论断保留出处（作者 年份: 页码 或课件页）；图片/图表 OCR 得到的数据标「OCR」来源。
4. 诚实原则：信息缺失如实标注（「未提供」+获取途径），**不编造**；多来源冲突时以书面大纲为准并在笔记注明。
5. 图片补充知识点（OCR 所得）单独成节，如 `Image Key Points — …（图）`，避免与文字层内容混淆丢失。
6. 课件内部自相矛盾时（如演示时长、成绩加总口径），**照录双方 + 标 ⚠️ 建议向老师确认**，不擅自选一个当事实。
7. 小组作业类文档的写法**分场景**：只有在**「组内分享想法、选题尚未定稿」阶段**给组员看的文档，才用 §八 的「简版风格」；交给老师的正式 outline、定稿后的提案与幻灯片、复习笔记、各类汇总文件**不套用**该风格，按各自规范来（见 §八 适用范围）。
8. **英文缩写首次出现必须给全称或解释**（实践约定）：任何大写缩写（ISI、EOI、NIEs、YEI、NEET、GVA、MEDCs/LEDCs、EPZ/FTZ、UNCTAD、NAM、RDM、HKSAR、NSL、PRC、OCR、ASR、MC、ASA、WWII、SDF…）在**全文第一次出现处**写成 `缩写（全称，中文）`，英文正文里也可写成 `Full Form (缩写)`；此后才可直接用缩写。**复习笔记、课程 README、课程总结、根目录汇总文件一律适用**（每份文档各自计数）。
   - 检查工具：`python3 scripts/acronym_check.py <文件或目录>`——扫出所有 2-6 位大写缩写，逐个检查首次出现处是否有全称/解释，输出问题清单（脚本内置常见无需解释的 SAFE 列表：HK/US/UK/UN/EU/AI/PDF/PPT/DDL/GDP/NGO/OECD 等）。
   - 交付前必须跑一次该脚本，**0 处问题**才算完成；以后新增缩写要同步补全称。
   - **人名**（如同学姓名、作者姓名）与**教室代码**（如 BC402、CD301）不算缩写，可忽略脚本的这类误报。

## 三、四层提取（每份新课件必做）

| 层 | 方法 | 工具/位置 |
| --- | --- | --- |
| ① 文本层 | PDF：`pdfplumber.extract_text()`；PPTX：解压读 `ppt/slides/slideN.xml` 的 `<a:t>`（推荐直接跑 `scripts/extract_pptx.py`，按形状坐标排序输出） | python3 |
| ② 表格/形状/SmartArt/图表 | PDF 表格 `page.find_tables()` / `extract_tables()`；PPTX 解析 `a:tbl`、`ppt/diagrams/`（SmartArt `data*.xml`）、`ppt/charts/`（`chart*.xml`），存在则单独解析 | python3 + zipfile |
| ③ 图片 OCR | `pypdf` 的 `page.images` 提图 → macOS Vision 框架 OCR（中英） | Swift，**需 full-access**（沙箱内 Vision 全部返回 `nilError`） |
| ④ 演讲备注 speaker notes | PPTX 的 `ppt/notesSlides/notesSlideN.xml` 里 `<a:t>` 文本（与 slideN.xml 按 N 对应） | python3 + zipfile |
| ⑤ 课堂录音/转写（若有） | 转写 docx 用 `python-docx` 读；先看结构（AI 摘要段 vs 逐字稿段），**按中文字符占比过滤掉机翻行**，只保留英文原声 | python3（本库实例：`语音_09101858.docx`、`录屏<日期>.docx`） |

- **课堂转写处理规则（实践立规）**：
  1. 转写常为「AI 摘要（发言总结/通用摘要/核心话题/会议纪要）+ 逐字稿（带时间戳，常"未区分说话人"）」——**摘要用于定位，逐字稿用于取内容**。
  2. 提取时按 CJK 占比过滤机翻行（阈值约 0.25），保留英文原声 + 时间戳，得到约半数体积的纯内容文本。
  3. 取舍三分：**课程要求/行政通知**（入 README/DDL/出勤汇总）· **知识性内容与老师口头结论**（入对应讲的复习笔记，独立成节如 `5.22 课堂实录 · …`）· **闲聊/技术故障/无关跑题**（弃）。
  4. **老师对讨论题的口头结论优先记录**（学生小组答案也一并记，标注"学生答案/老师点评"），因为这类内容课件上没有。
  5. **免责标注**：ASR + 机翻易错（人名、术语、数字），笔记须注明"引自课堂实录，引文以课件/原著为准"，不作精确引用来源。
  6. 转写文件按原名归档进该课文件夹，并在该课 README 文件清单登记。

- **PPTX 首选工具**：`python3 scripts/extract_pptx.py <file.pptx> [--from N --to M] [--images-dir DIR]`
  一次输出：按坐标排序的文本、`[TABLE]` 逐格表格（`a:tr`/`a:tc`，保留单元格边界）、`[图片 xN]` 占位、`[NOTES]` 备注、图表数据点、以及可选媒体导出。**表格必须用它的 `[TABLE]` 输出，不能用扁平文本顺序**。

- **speaker notes 不要跳过**：老师备注多为参考文献与页码指引（如 "Esping-Andersen (1990), p.19"），是把笔记术语精确对回原著的唯一线索；notesSlide 数量多（如 49/54）时按 slide 号并入对应小节即可。
- **0 字符页必查图片**：先统计每页文本字符数，0 字符/极少的页默认含整页图（地图、图表、海报），必须走 ③。
- OCR 脚本易被清（/tmp）：持久版在本 skill `scripts/vision_ocr.swift`（或按快照重建）；swiftc 编译加 `-module-cache-path /tmp/mc` 规避沙箱 ModuleCache 拒绝。**沙箱下 `swift vision_ocr.swift` 会返回 `[ERROR nilError]`**（Vision 模型访问被拒）；改用 `image_ocr` 工具（engine=macos）读同一张 PNG 即可，必要时用其 `region` 参数放大局部（先 `image_crop` 或 `region` 均可）。
- **PDF 图表页要渲染出来再 OCR**：`swift scripts/pdf_render.swift <pdf> <outDir> [scale=3.0] [页列表|all]`（PDFKit 渲染为 PNG，默认 3.0≈216dpi）。PDF 的图片型图表在 `extract_text()` 里往往只剩标题与 source 行，数据必须走这一层。渲染后先 `image_ocr` 全页，若关键列仍不可读，再 `image_ocr region` 或 `image_crop` 放大重读。

## 四、表格处理铁律 ★★（所有载体、所有表格一律适用）

> 立规原因：曾用扁平文本读取 5 栏官方时间表，按文本流顺序推断列归属，把 **MNOP3456（Thursday 列）误记为周三**，并由此写出错误的排课冲突结论。凡表格，**结构必须从单元格来，绝不能从文本流来**。

### 4.1 通用铁律
1. **结构优先**：表格一律按单元格读取。PDF → `find_tables()`/`extract_tables()`；PPTX → `a:tbl` 的 `a:tr`/`a:tc`；docx → `table.rows[i].cells[j]`；图像表格 → OCR 后必须做行列锚点校验。
2. **禁止**用扁平 `extract_text()`（或 slide 级 `<a:t>` 顺序）判断表格中任何单元格的**行/列归属**，更不得据此填写数值、日期、星期、时间、地点、权重。
3. **先定位表头再映射**：取表头词的坐标（`extract_words()` 的 `x0`/`top`）→ 得出列边界 → 单元格按 x 归列。无法确定归属时**标注「待核对」，不得猜**。
4. **关键字段逐格核对**：日期 · 星期 · 时间 · 地点 · 成绩权重 · 字数 · 页码 · 课程代码 · 人名 · 金额 —— 必须逐格对照原表，禁止由上下文推断。
5. **单元格保真**：原表空格保持空，**不得把邻列值左移补空**；合并单元格在提取结果中可能重复出现，写入时只保留一次并注明「跨行/跨列」。
6. **数字自检**：权重/百分比/学时类表格必须验算合计（总分应为 100% 等）。**不吻合时照录原文 + 标 ⚠️ 待确认**，绝不自行改写数字或"补齐"。
7. **版本与来源优先序**：同一表格在多个文件/版本间冲突时 → 最新课件 + 书面大纲 > 旧版课件；差异要写进笔记与该课 README（注明版本与独有内容）。

### 4.2 各载体操作要点与常见坑
| 载体 | 正确做法 | 常见坑 |
| --- | --- | --- |
| **PDF 表格** | `page.find_tables()` / `page.extract_tables()`；线框缺失时用 `table_settings={"vertical_strategy":"text","horizontal_strategy":"text"}`，或用表头 x 坐标自定义列边界 | 多栏版式（时间表、日程）列错位；跨页表被截断；单元格内换行被合并；表头跨列导致值整体偏移 |
| **多栏文本框（非表格）** | `extract_words()` 按 `top` 分行、按 `x0` 归栏还原（详见 §4.5a） | **左右两栏会被文本流交错串行**，长条目误挂到另一栏；两栏条目数不等时更易错 |
| **PPTX 原生表格** | 解压后按 slide 定位 `p:graphicFrame → a:graphicData → a:tbl`，逐 `a:tr`/`a:tc` 读取 | 用 slide 级 `<a:t>` 顺序读会丢失单元格边界，把多列数值串成一行 |
| **PPTX SmartArt** | `ppt/diagrams/data*.xml`（`dgm` 命名空间） | 文本不在 slide XML 中，纯文本提取不到 |
| **PPTX 图表** | `ppt/charts/chart*.xml`：`c:cat`（类别）+ `c:val`（数值） | 靠看图片估数值会误读；**不要**用图片 OCR 替代 chart XML |
| **图像表格/图表** | Vision OCR 后与同页正文或官方 "Interpretation" 行交叉验证；**统计图必须按 §4.5b 的"网格线标定 + 颜色掩码逐列取数"读**，禁止目测 | 数字 OCR 易错（0/8、1/7、千分位）；推算值标「≈」并写出推算依据；曲线端点年份越界时不要硬推 |
| **docx 表格（读）** | `table.rows[i].cells[j].text`；注意合并单元格会在同一行重复返回同一对象 | 直接按 `len(row.cells)` 推断列数会多算 |
| **docx 表格（写）** | **先清空既有 run 文本再写**；跨行/跨列合并单元格不要重复写；写完**重新 dump 全表**核对 | 直接 `add_run` 会追加重复文本；只改一个 run 而文本被拆到多个 run 时替换失效（必要时重建整段） |
| **md 表格** | 表头行 + 分隔行缺一不可；列数全表一致；单元格内的 `|` 改为 `/` 或转义 | 列数不齐会被补齐/错位；`|` 截断单元格；空单元格丢失导致后续列左移 |
| **md→docx 管线** | 转换后统计表数量与关键单元格内容 | 只信"转换成功"而不校验内容；表格数量或单元格串位无人发现 |

### 4.3 配套工具（强制使用，别靠记忆）
`python3 .claude/skills/polyu-courseware-notes/scripts/table_qa.py`
| 命令 | 用途 |
| --- | --- |
| `pdf <file.pdf> [--page N] [--compare]` | 结构化读 PDF 表格（`find_tables`，无框线自动退化为 text 策略）+ 打印**表头 x 坐标**（判断列归属的唯一可靠依据）；`--compare` 同时打印扁平文本，用于发现"文本流顺序 ≠ 单元格顺序"的错位陷阱 |
| `pptx <file.pptx>` | 导出 PPTX 原生表格（`a:tbl` → `a:tr`/`a:tc`）逐格内容，含合并单元格提示 |
| `extract_pptx.py <file.pptx>` | PPTX 四层一次性提取：坐标排序文本 + `[TABLE]` 逐格表格 + 图片清单 + `[NOTES]` 备注 + 图表数据 |
| `docx <file.docx>` | 导出 docx 全部表格（行列号 + 内容，合并单元格标 `⟦merged⟧`）；含 `set_docx_cell()` 安全写单元格写法（清空既有 run 再写） |
| `sums "40%" "10%" ...` | 合计验算：全为百分比时自动判定是否 =100%，不吻合即提示"照录原文 + 标待确认" |

> 事故复现验证：对 `<某课程>时间表.pdf` 运行 `pdf … --page 1`，输出第 1 行单元格 `['3:30 p.m. - 6:20 p.m.', '', '', '', 'MNOP3456 (R) …', '']` —— MNOP3456 明确落在 **Thursday** 列（索引 4），本可避免这次误记。

### 4.4 每次表格操作的强制质检（做完立即执行）
1. **行列数核对**：提取结果的行数/列数 = 原表行数/列数（含表头）。
2. **表头核对**：列名逐一相符，顺序一致。
3. **关键字段抽查**：数值/日期/星期/权重列至少抽 2 行与原文件逐字比对。
4. **合计校验**：有权重或合计行/列的表必须验算；不吻合即标 ⚠️。
5. **回写校验**：写入 md 或 docx 后重新 dump 该表，确认无丢行、无串列、无重复、无空单元格左移。
6. **交叉来源校验**：与第二来源（大纲/AR/官方时间表/上一版课件）比对；冲突必须记录并标注待确认。
7. **日期—星期一致性**：课件里的日期与其"固定上课星期"对照（如某课固定在周四，则所有课次日期都应是周四）；不一致处标注推断与依据，并列入"待老师确认"。

### 4.5 双栏文本框与「图内数据」的读取 ★（立规，来源：IJKL9012 L6 slide 11 / slide 10）

> 立规原因：L6 slide 11 是**左右两个文本框**（不是表格），`extract_text()` 把两栏交错串行，**"Long time horizons for capacity-building" 会被误判到右栏**；同讲 slide 10 是**截图型统计图**，只能读像素。两类都不是"表格"，但同属"结构必须从坐标来"。

**(a) 多栏文本框（不是表格，但同样会串行）**
1. `page.extract_words()` → 按 `top` 分行（`round(top/6)` 作 key）→ 每行内按 `x0` 升序。
2. 观察 `x0` 是否分成两组（本库例：左栏 x≈64-360、右栏 x≈358+）→ 以栏边界分组还原。
3. **左右条目数不等时，禁止一一对应**：slide 11 左栏 5 项、右栏 4 项；必须逐条按 x 归栏，不得按文本流顺序配对。
4. 写入笔记时在表格下注明"**已按词的 x 坐标逐格还原**"，并把易错的那一条单独提示。

**(b) 以图片形式出现的统计图（无 chart XML 时必须读图）**
- 仅当 PPTX 存在 `ppt/charts/chart*.xml` 时才读 XML（§4.2）；**PDF 导出页、截图、整页图片中的图表没有 XML，只能读图**。
- **禁止目测估数**，按以下步骤得到可复核的近似值：
  1. **渲染**：`pdf_render.swift`，或 LibreOffice 转 PDF 后用 `pymupdf` 渲染，≥170 dpi。
  2. **找网格线标定坐标轴**（比 OCR 标签更稳）：图像转 numpy，取灰像素掩码 `(max-min<14) & (140<max<249)`；按列/行计数，**计数超阈值（如列 680 像素中 >150、行 1300 像素中 >250）的位置即网格线**；相邻网格线间距 = 一个刻度间距。
  3. **OCR 轴标签做交叉验证**：`image_ocr`（engine=macos）读 `30000 / 25000 / … / 0` 的 bbox 中心，与第 2 步的网格线位置对照，吻合才继续。
  4. **提取数据系列**：按该系列的颜色掩码（例：蓝色 `(B>195)&(B-R>55)`）**逐列求像素 y 均值** → 用第 2/3 步的线性映射换算成数值；导出每 5 年一个读值。
  5. **报告口径**：写"**为读图近似值（±数百）**"，并注明纵轴范围、刻度与曲线起止；**曲线的端点年份若越出最后一个刻度，只写"右端接近纵轴上限"，不要硬推年份**。
- 若图内只写了一句 "Source: X (year)"，**引用写"转引自课件 slide N"**，不要替它补数据机构或推测原始序列。
- 依赖：`PYTHONPATH=./.pylibs python3`（Pillow + numpy 已在库内）。


## 五、生成 docx（md → Word）

- 持久脚本：本 skill `scripts/md_to_docx.py`（python-docx，正文 Calibri + 中文字体微软雅黑，含标题/表格/列表/粗体/引用支持）。
  **用法（现行规则：必须显式传参）**：`python3 scripts/md_to_docx.py <in.md> [out.docx]`。
  ⚠️ **不要再无参数直接运行**——旧版本会把全库每门课的 `复习笔记.md` 各转出一个**合并版 `复习笔记.docx`**（违反"一讲一个 docx"规则）；新版无参数会打印用法并退出，合并版转换被挪到显式的 `--all-notes` 之下并附警告。
  单文件转换（如 `工作日志_*.md`、`课程总览.md`）才用这个脚本；**按讲拆分一律用 `split_to_lectures.py`**。
- **按讲拆分**：`python3 scripts/split_to_lectures.py <课程>/复习笔记.md --prefix <课程代码>_`
  ⚠️ **必须带 `--prefix`（现行硬规则）**：脚本输出的默认文件名是裸的 `复习笔记-第N讲.docx`，**不带课程代码前缀**，与命名约定 ① 的 `<课程代码>_复习笔记-第N讲.docx` 不符；不加 `--prefix` 会在课程文件夹里多出 6 个重复文件（同名不同前缀），极易被当成两份笔记。脚本现已支持 `--prefix`（自动补末尾下划线），**一律显式传入**，如 `--prefix QRST7890_`。
  默认按 md 中 `## N. Lecture M — …`（讲号后须接 `— – - : ( （` 之一）切讲，自动生成该课每讲的 `<课程代码>_复习笔记-第N讲.docx`。
  **各课标记变体（务必对照，用错则切不出讲或误切）**：
  | 课程 | md 中的讲边界写法 | 命令 |
  | --- | --- | --- |
  | ABCD1234 / EFGH5678 / IJKL9012 / MNOP3456 | `## 4. Lecture 1 — …`（小节 `### 4.1 …`） | `--prefix <代码>_`（标记用默认） |
  | **QRST7890** | `# Lecture N: …`（一级标记 + 全课连续编号 `## 1..23..`） | `--prefix QRST7890_ --lecture-markers '^#+\s*(Lecture)\s+(\d+)\b'` |
  自定义正则必须含 **2 个捕获组且第 2 组为讲号**；脚本会校验并在不符时报错退出。
  **重新生成后核对一致性**：docx 的小节号序列应与 md 该讲完全相同（如 QRST7890 第 6 讲两侧均为 §93→109、28 节、12 表），段数与表数对齐才算同步完成。
- **表格单元格内不要用 `**`／`*` 强调**（实测）：`md_to_docx.py` 对**嵌套强调**（如 `**OECD, *Pensions…* 2023**`）处理不干净，星号会原样漏进 docx 单元格。表格内一律写纯文本，强调放到正文段落里。校验方法：转换后遍历所有 `cell.text`，**不得出现 `*`**。
- 转换后必做质检：打开每个 docx，确认（a）标题层级连贯、（b）**表格数量与单元格内容逐格不丢**（对照 §四 4.3）、（c）**只含对应讲的内容**、（d）中文正常显示（eastAsia 字体已设）、（e）**无 `---`／表格分隔行等 md 语法残留**。
- 生成后删除任何遗留的合并版 `复习笔记.docx`（除非该课确实只有一讲且按规则命名）。
- 改动脚本或标记方式后，**必须回归验证**：重生成已发布的讲次 docx，与新版本做段落级 diff，确认旧讲内容零差异（曾以此做回归验证 QRST7890 第 2 讲 0 diff）。

## 六、每份课件处理流程（Checklist）

1. 归档：新文件 → 对应课程文件夹（**仅限工作区 `PolyU/` 内的根目录散文件**；重复文件先比 md5，相同则删冗余副本，不同则按版本并存）。**不要到工作区外找文件**；工作区内没找到就先问用户（见 §一第 6 条）。
2. 提取：按 §三 四层走一遍（文本 / 表格·SmartArt·图表 / 图片 OCR / speaker notes）；0 字符页必须 OCR；**表格一律走 §四 铁律与质检**。
3. 更新 `复习笔记.md` 总源（新讲 = 新小节，含 class business/行政宣布等可考或待办信息）；若该课 md 尚无讲次标题，先把课程级小节（框架/考核/GenAI/阅读清单）移到讲次块**之前**，再加 `## N. Lecture M — …` 标题。
4. 运行 §五 脚本重生成**该讲** docx；必要时把历史合并 docx 拆掉。
5. 更新该课程 `README.md`：文件清单、「各讲知识点」摘要、（如有）DDL/出勤/教师/上课时间变更。
6. 影响课程级信息时同步根目录：`README.md`、`DDL汇总.md`、`出勤规定汇总.md`、`AI使用红线速查.md`、`课程总览.md`、对应课程 `<课程代码>_课程总结.md`、`会话交接快照.md`（结构树 + 待办 + 已修正记录）。
   ⚠️ **必须改 `.md` 源再重新生成 docx**——这些总结原先只有 docx（孤本），改了源也不会传导过去，曾出现**五份总结全部停留在 9 月中旬**（漏掉 10/22 中午补课、11/12 报告、课室变更等）。
   **收尾必跑**：`python3 scripts/sync_check.py`，必须输出「全部同步 ✓」；不清净就按提示逐个重生成。
7. 完成前用 `ls` 核对产出文件存在；向用户汇报「新增/变更文件 + 要点速览 + 待外部输入项」。

## 七、写作/转换后复查

- 复习笔记 docx 只按讲独立、md 总源最新 —— 实践约定的形式规则，**后续所有笔记均须遵守**。
- **表格零容忍**：任何进入笔记/README/汇总的表格数据，都必须经过 §四 4.3 的六项质检；无法核实的标「待核对」，不得猜测（实践约定：所有表格处理错误以后一律避免）。
- 课程级事实改动后，同步链路（**每一步都先改 .md、再生成 .docx**）：课程 `README.md` → 根 `README.md` / `课程总览.md` → `DDL汇总.md` → `出勤规定汇总.md` → `AI使用红线速查.md` → `<课程代码>_课程总结.md` → `会话交接快照.md`（并记「已修正记录」一条）。
  **机械校验（实践立规）**：跑 `python3 scripts/sync_check.py` 检查「md 比 docx 新」的过期项；带 `--fix` 可自动重新生成（复习笔记须另用 `split_to_lectures.py`）。**这是防止交付物悄悄过期的唯一机械手段**——靠记忆一定会漏（本次就漏了 6 份总结 + 2 套复习笔记）。
  **docx 孤本一律补 md 源**：发现只有 docx 没有 md 的文件（如旧版课程总结），用 `python3 scripts/docx_to_md.py <file.docx>` 反向导出成 md 再维护，别继续在 docx 上原地改。
- OCR 数据与文字层互相印证；数字类图表数据只写图上明确出现或能由官方解读行推算的值，推算值加「≈」与推算说明。
- 引用格式若课件/大纲有要求（如 APA/Harvard）在笔记示例中体现。
- 交付前自问四句：**这张表是逐格读的吗？关键字段核对过吗？合计/星期对得上吗？缩写首次出现有全称吗？**
- **缩写检查**：每次新增或更新笔记/汇总后运行 `python3 scripts/acronym_check.py .`，必须 0 处问题（详见 §二第 8 条）。
- **回答课件讨论题（实践立规）**：用户问某页/某题怎么答时，**先取课件原文 + speaker notes + 课堂转录**（顺序：笔记 → `extract_pptx.py` 该页 → notesSlide → 课堂转写），再考虑补充外部文献。答案中**逐条标出处**（课件 slide N／课堂原话／「我补的文献」／「我的推断」），**看不到的材料（视频、录音）要明说看不到**并把"可由课件确定的部分"与"必须看片才能确定的部分"分开写。教训来源：曾有一次未先查课程材料、仅凭方法论知识作答，被指出"并不完全正确"；而答案其实就在课堂转录的 Q&A 段与 speaker notes 里。**课程题按课程的概念体系回答，外部理论只作补充。**
- **记录事实要标证据强度（实践立规）**：写「用户告知」之前先确认有没有直接原话；仅由文件、时间戳、间接线索推出的结论，一律写成「据 X 推断，待确认」，**不得与用户明示混写为一句事实**。教训来源：把"用户把课件样例文件放进工作区"记成了"用户告知小组选题＝Volkswagen 排放门"，错误记录存活五天；后经课件 p12「Two examples for your assignment」证实该文件只是老师给的样例。
- **外部共享链接默认只登记、不访问、不修改**（实践约定）：Google Docs 等他人共享文档只在本地记录链接与用途；**读取与修改是两件事**——用户明确要求核对时可做只读抓取（`/mobilebasic` 可取全文、`/edit` 视图会被截断、`export?format=txt` 跨域重定向），但任何情况下不得写入或改动；其余需要内容时请用户粘贴提供。

## 八、组内选题阶段文档（限定场景，勿外推）

> **适用范围（严格限定，用户明确）**：**仅适用于「给小组成员查看、分享想法、选题尚未最终确定」这一阶段**的文档。
> **不适用**：① 交给老师的正式 outline 与课程提交件；② 选题定稿后的研究提案、幻灯片、报告；③ 复习笔记与根目录各汇总文件；④ 其他课程／其他任务的任何文档。
> 换句话说：§八 的规则是**这一个场景的临时约定**，不能被当成全库通用风格。今后遇到同类场景（组内分享、比较不同成员的选题）才启用；一旦选题定稿、文档要交给老师或对外提交，回到课程要求与常规写法（该详细就详细，可用表格、分级标题与规范术语）。

**内容范围（只保留选题本身）**
- 保留：题目、要解决的问题、研究问题、关键概念、方法与局限、创新点；再按该作业的要求逐项补齐（如循证作业要写政策问题与原始研究问题、研究方法与发现、研究怎么影响政策、参与各方、研究优劣、政策启发）。
- 删掉（这些属于组内行政，组员看选题时不需要）：作业要求与评分细则的复述、评分逐项对照、分工与时间表、问答准备、下一步待办、与另一份作业如何衔接、版本说明。
- 一个文档一个题目。若处在"比较不同成员的选题"阶段，各候选选题分开成文、格式一致，便于并排对照；**不要在一份文档里并列多个候选题目**（实践约定"不用提出多个题目"）。
- 允许把两份作业合并成一份（要求）：按任务分段，每段只写选题内容。

**写法（"简版风格"）**
- 排版只留两级：文档标题 + 小节标题；正文不再分字号（正文 10.5 / 小节 13 / 标题 16 已是上限）。
- 不用斜体（含 md 的 `>` 引用块，转换器会渲染成灰色斜体）、正文不用加粗。
- 尽量不用表格，把表格内容改写成短句或分行短句。
- 少用符号：不写 `→ ｜ ① ★ 「」 【】 ⚠️`，改用中文标点与"第一/第二/然后/另外"这类连接词。
- 措辞口语化：避免"映射／闭环／操作化／必要而非充分条件／因果链／抓手"等术语堆叠，改说"研究发现怎么影响了政策""好处在哪、问题在哪""上台前要先查清的事"。
- 篇幅：默认**控制在 1,000 字以内**（实践约定"一千字以内"）；短句分行，一段说一件事。写完用 `len(re.findall(r'[\u4e00-\u9fff]', 正文))` 数一下汉字，并把**含标点总字符数**一并核对，两者都要在限内。
- 事实类内容照旧遵守诚实原则：拿不准的政策细节、研究出处、数据，写成"要查清的事"列在文末，不编造。

## 九、做 PPT（.pptx）的工作流与协作约定 ★（实践立规）

> 📌 改完 PPT 必须用 **LibreOffice 渲染出来实际看一遍**——见独立 skill `ppt-authoring`。

> **触发**：用户给一份 .pptx 模板／现有 deck，加一部分内容，要求"把这部分做成 PPT"。

**环境现状（必须先知道）**
- `python-pptx` 装在**工作区内** `./.pylibs`，调用一律 `PYTHONPATH=./.pylibs python3 …`；不装进系统环境。
- **本机无渲染器**：没有 PowerPoint／Keynote／LibreOffice；WPS 只有 GUI、无 CLI；macOS 自带 `qlmanage` 在本环境报 `sandbox initialization failed`。→ 现状下**看不到成品**，只能按几何测量验排版，并如实告知用户"没渲染过"。
- **用户若装了 LibreOffice**（若已装，26.2.6.3，Apple Silicon）：**必须加 `-env:UserInstallation`**，否则因沙箱无法写默认用户目录而报 `DeploymentException / Unspecified Application Error`：
  ```bash
  P="file://~/PolyU/.render/lo_profile"
  HOME="$PWD/.render" /Applications/LibreOffice.app/Contents/MacOS/soffice \
    -env:UserInstallation="$P" --headless --norestore --convert-to pdf --outdir .render <file.pptx>
  ```
  再用 PyMuPDF 读**精确坐标**复核：`pymupdf.open(pdf)` → `page.get_text('blocks')` 给出每个文本块的 `(x0,y0,x1,y1)`，**除以 72 得英寸**，直接算重叠（比肉眼看准）。渲染成图用 `page.get_pixmap(dpi=110).save('PN.png')`。
  注意：`image_scan` 在 40 格粗网格下**看不见细字**（只剩装饰图形），要判断文字位置请用 PDF 坐标提取，或用 `image_ocr`（**须指定 `engine="macos"`**，默认的 windows 引擎在本机会报 `spawn powershell.exe ENOENT`）。
- **模板标题框是底部对齐的**（实测）：文字贴着文本框**下边**生长、向上溢出，所以**标题位置由框的 bottom 决定，动 top 等于整体平移**。缩小字号后**不要下移**标题框——下移会把标题推进正文。正确的做法是保持模板原有的 top，让 bottom 与设计一致。

**继承模板设计（最稳的做法）**
- **整页复制 XML**，不要用 `add_slide(layout)` 重建：模板的设计多在幻灯片自身的形状里（装饰 freeform 带图片填充），版面是 Blank。
- 复制 `ppt/slides/slideN.xml` 与 `ppt/slides/_rels/slideN.xml.rels`，再到三处登记：`[Content_Types].xml`、`ppt/_rels/presentation.xml.rels`、`ppt/presentation.xml` 的 `<p:sldIdLst>`。**只加 sldId 不够**——装饰图形靠该页自己的图片关系，必须连 rels 一起复制。
- 幻灯片**显示顺序由 `<p:sldIdLst>` 决定，与 slideN.xml 的编号无关**；插页要插在 sldIdLst 的正确位置（插到"最后一个 sldId 之前"用 `re.sub` 把新项放在匹配项前面）。
- 删除模板原有页要**四处同步删**：slide 部件、其 rels、内容类型 Override、presentation.xml.rels 里的关系项。

**改文字（保留格式）**
- 用 python-pptx：**保留第一个 run、删掉其余 run**，再写新文本——字体、字号、颜色、行距、autofit 全部继承。
- 多行要点：`copy.deepcopy(段落 XML)` + `addnext()` 克隆（用 `prev=newp` 顺序追加），**不要新建段落对象**。
- **不覆盖原件**，一律另存新名；交付前做完整性校验：① 每页用到的 rId 都在同页 rels 里；② 所有 rels 的 Target 都存在；③ 内容类型覆盖所有部件。

**排版自检（看不到图时）**
- 行数用**固定行距**换算：`行数 × 行距pt ÷ 72 = 高度`，加文本框顶边后须小于幻灯片高度并**留 ≥1 英寸余量**（文本框若为 `spAutoFit` 会向下生长）。
- 每行字符数按 `框宽pt ÷ (字号 × 0.5)` 估算（西文）。
- **标题从单词变多词必须缩字号**：131pt 下约 0.9 英寸／字符，11.84 英寸的框只放得下 10 个字符左右；两三个词的标题用 72pt 较稳。

**协作约定（用户侧）**
- 需要用户提供：**.pptx 原件**（不是截图）＋ **该部分的内容文本** ＋ **一句说明**（总时长／这部分几分钟／几页／中英文）。
- 要并进大 deck 时**交独立小 deck**，不动别人的页，方便直接拖入。
- 改稿请报**页码＋问题**，便于精确补丁，不必重做整份。
- 稿子与 PPT 一起给，保证两者用词一致。

**做不到的**
- python-pptx 不建模动画、切换、SmartArt。整页复制能保留模板页已有的动画与图形；**从零造 SmartArt、改图表数据不做**，这类需求交回用户在 PowerPoint／WPS 里手动完成。

## 十、给 PPT 加「逐页录音旁白」★（实践立规）

> **触发**：小组作业要求「把 PPT 做成已录音的版本」，或用户说别的组员都交了带旁白的 deck。

**先认清目标产物（别答错）**
"已录音的 PPT" 不是交一个 mp4，而是**音频按页嵌进 .pptx**：打开就能一页页自动播。判别方法（拿一份现成的拆开看）：
- `docProps/app.xml` → `<Application>Microsoft Macintosh PowerPoint</Application>`、`<MMClips>4</MMClips>`（媒体片段数）、`<TotalTime>`
- 每页 `ppt/slides/slideN.xml` → `<p:audio isNarration="1">`、`<p:transition … advTm="毫秒">`（advTm 必须等于该页音频时长，否则翻页会对不上）
- `ppt/media/mediaN.m4a` ＋ 该页 rels 里两条关系 → 这就是 PowerPoint 的**「幻灯片放映 → 录制幻灯片演示」**产物。

**本机现状（决定了只能走哪条路）**
- **没装 PowerPoint**；有 WPS（Mac 版自带 `screenrecorder` 组件，但输出是 mp4，做不到"音频嵌进每页"）＋ LibreOffice（只渲染）＋ QuickTime／语音备忘录（系统自带）。
- **用户可免费用 PolyU 的 Microsoft 365**（含 PowerPoint for Mac）：<https://www.polyu.edu.hk/its/faq/index_detail.php?id=47>，用 PolyU O365 账号登录订阅。这是唯一能一模一样复刻组员产物的路。
- **不装 PowerPoint 也能做出同样结构**：让用户按页录音（一页一个文件），由 `embed_narration.py` 封装。

**`scripts/embed_narration.py`（封装器）**
```bash
# 放置：<audio_dir>/1.m4a 2.m4a … 数字 = 幻灯片页码（也认 01.m4a / .mp3 / .wav）
python3 scripts/embed_narration.py <deck.pptx> <audio_dir> [out.pptx]
python3 scripts/embed_narration.py --verify <deck.pptx>      # 逐页核对旁白与 advTm
```
对每一页做四件事（顺序与 PowerPoint 一致，**照抄真实产物、不要自创**）：
1. 音频写入 `ppt/media/narrationN.<ext>`；`[Content_Types].xml` 注册 `<Default Extension="m4a" ContentType="audio/mp4"/>`
2. rels 里加**两条**指向同一音频的关系：`.../relationships/audio`（给 `<a:audioFile>` 用）＋ `http://schemas.microsoft.com/office/2007/relationships/media`（给 `<p14:media>` 用）；再加一条 image 关系给图标海报
3. `</p:spTree>` 前插 `<p:pic>` 音频承载形状，`p:cNvPr@id` 即 timing 里引用的 `spid`（**取该页现有最大 id + 1**，各页 id 不同，不能写死）
4. `</p:sld>` 前按 `CT_Slide` 的**固定顺序**插 `<p:transition advTm="毫秒"/>` 再插 `<p:timing>`（顺序：cSld → clrMapOvr → transition → timing → extLst，反了 PowerPoint 会报错）

**两个必须记住的坑**
- **海报图用 1×1 全透明 PNG**（脚本用 zlib 手搓，不依赖 Pillow），放进右下角同一坐标 → 音频照常播放但**幻灯片外观零变化**，不会给用户的 deck 平添一个喇叭图标。验法是解 `IDAT` 看 RGBA 是否 `(0,0,0,0)`。
- **时长必须实测**：macOS 用 `/usr/bin/afinfo`（`estimated duration:` 行），失败回退解析 MP4 `mvhd` 原子。**不要用词数估算填 advTm**。

**录音稿要单独出**
- 讲稿里的分页提示词（本项目用 `NEXT` 独占一行）切成 N 段 → 一段一页，正文别混在一起。
- 录音稿按页给：页码 ＋ 页标题 ＋ 词数 ＋ 目标秒数（按 150 wpm 折算）＋ 目标文件名，正文照样遵守"英文在前、中文整段挪到最后"的既有约定；写明**不要念 NEXT**。
- 目标时长只是参考，实际差几秒无所谓——advTm 读真实音频长度。

**验证（缺一不可）**
1. 全部 part 用 `ET.fromstring` 过一遍，确认 XML 合法；`zipfile.testzip()` 无损坏。
2. `python-pptx` 能打开、页数不变。
3. LibreOffice 渲染成功（能渲出 PDF 就说明包结构被独立实现接受）；渲染时出现 `cannot create appearance stream for Screen annotations` 是**正常且是好信号**——说明音频被识别成了媒体对象；原始 deck 渲染应无此提示。
4. 原始 deck 与成品 **逐页文字提取零差异**（`"".join(page.get_text().split())` 相等），证明版式没被破坏。
5. 像素比对若只在右下角落有差异（`diff_ratio` ≈ 0.004、`diff_box` 落在音频图标矩形内），那是 MuPDF 给 Screen 注释画的占位框，**不是可见图标**，可放行。

## 十一、演讲稿要「能念」★（实践立规）

> **触发**：写或改任何要被读出来的稿子（讲稿、录音稿、presentation script）。用户判断标准是**念出来顺不顺**，不是写出来好不好看。

**硬指标（改完必须量化自检）**
- **平均 ≤ 11 词/句，且不得有任何超过 22 词的句子。**（本项目终版：54 句 / 平均 10.5 词/句 / 0 句超标）
- **不得有超过 13 个词的无标点长串。**唯一例外是全文的论点句，且必须是工整的平行结构。
- 词汇表里不应出现 4+ 音节的生僻词；无法避免的行业分类词（如 `policymakers`）要确认它同时出现在幻灯片上。
- 书面腔词表一律清零：`such as`（口语用 `like`）、`shall`、`thereby`、`in terms of`、`with regard to`、`utilise`。

**七类「念出来很怪异」的病因与改法**
1. **逗号插入语当绊脚石** —— `personal data, once collected, cannot be taken back` → `once personal data is collected, it cannot be taken back`。念到插入语要换气，听众会断线。
2. **超长名词串** —— 最糟的是把机构全名塞进列表首项（`the cybersecurity review run by the Cyberspace Administration of China`，11 词）。改成 `China's cyberspace regulator` 或把机构降级为句子主语。
3. **列表项长短悬殊** —— 四项并列里第一项 11 词、其余 3 词，念起来节奏崩掉。要么全部压到同长度，要么拆成独立短句。
4. **被动语态堆叠** —— 14 处被动里凡是可以改成主动的都改（`the screen where the user agrees must be clear` 优于 `the agreement must be reversible`）。
5. **抽象名词当动词用** —— `records of what is kept must be retained` → `companies should keep a record of what data they hold`；`automatic yes answers` → `fewer permissions should be switched on by default`。
6. **反复出现的连接词** —— 连续几句都用 `And` / `So` 开头会腻；但短句之间用 `And` 起头反而比逗号连接自然，可保留少量。
7. **同一个词在同一段里重复** —— 论点句 `...to collect data is not the same as having ethical approval to collect it` 结尾的 `to collect it` 改成 `to do it`，立刻顺了。

**流程**
- **报告原句优先，绝不自行改写。**（用户明确要求，优先级高于本文其余所有风格规则）若正式的书面报告已有对应段落，讲稿必须**照抄报告原句**，只允许做朗读上必需的四类改动：① 分号 → 句号；② 去掉括号与引号；③ 标题式冒号 → 句号；④ 加最小过渡句。用户润色过的句子刻意压低了 AI 痕迹，任何"顺一顺"的改写都会把它改回去，属于倒退。
- 因此上面那套「平均 ≤11 词/句」的硬指标**只在没有报告原句可用时才适用**。报告原句本身就长（本项目 5 句超过 24 词），**不许拆**，改为在录音稿里用斜杠标出换气点。
- **保真校验必须做**（用数字证明没漏没编）：① 报告段落逐句在讲稿中做归一化子串匹配；② **多重集词差** `Counter(报告) - Counter(讲稿)` 必须为空（本项目最后只剩一个 `etc.`，补回后归零）；③ 讲稿多出来的词必须**全部**能归因到自己新增的过渡句。
- 讲稿与录音稿必须**逐字一致**（含中文段），改一处两边同时改，改完做 `sp_en == rec_en` 全等比对（比对时忽略换气斜杠）。
- 报告里明显不通顺但属于用户原话的句子（如 `the harm ... was given to those who were not involved`、`he or she tries to track users`、`ban of bundled feature`），**保持原样写进讲稿，另附一份"可选微调"清单交给用户决定**，不要擅自改。

## 十二、判定「实际授课顺序」（立规，来源：用户点出文件时间戳也是证据）★

**核心方法：课件进入工作区的文件时间戳 ＝ 实际上课日的客观记录。** 用户习惯在**当次课堂时段前后**（多数是开课前 0–10 分钟）把课件放进工作区，所以**上传日 ≈ 上课日**。遇到「大纲说这周讲 A、但实际好像讲的是 B」时，**先查时间戳，不要靠大纲推**。

**用法**：
1. 列出某课文件夹里所有课件的时间戳（`stat -f "%Sm|%N"`），对照该课**固定上课时段**。
2. 落在**当天该时段** → 当天就是那一讲的上课日，**可直接定案**。
3. 不在该时段 → 再看**那天有没有别的课的料进来**（可能是归属记错），再判是否属「老师延迟上传」。
4. **判不了就写「待确认」并列出两种读法与各自证据，交用户或老师定。绝不猜。**

**这套方法已实锤解决的问题**（详见根目录 `课件上传时间线.md`）：
- **QRST7890**：L1–L5 全部落在**周一**课堂时段 → 证实「**第 4 周起比大纲前移一周**」（大纲把 Globalisation 列第 5 周，实际 9/21 就上了）。⚠️ **唯 L6（族裔）上传于 10/14 周三 20:05，10/5 与 10/12 均无 QRST7890 文件，故 L6 落在哪一周无法用时间戳区分——仍在待确认。**
- **EFGH5678**：10/8 上传的是 `Week 6`、10/15 是 `Week 7` → 证实「**课件名按周次、实际是第 N 次课**」（10/1 停课造成差 1）。
- **MNOP3456**：v3 课件上传于 **9/23 19:07**（工作坊 3 的前一天）→ 证实 **工作坊 3 ＝ 9/24**，课件内页印的「9月14日」确为笔误。
- **ABCD1234 / IJKL9012**：七讲逐周对齐、**无错位**（可用于排除「是不是也前移了」的疑虑）。

**局限（必须一并说明）**：
- 课件**延迟上传**时，只能确定「不晚于上传日」，无法锁定具体哪一周。
- 开课前发的材料（AR／SDF／v1 课件）会**提前**数天出现，不代表上课日。
- 用户事后补传历史文件同样会造成假信号。

**顺带**：这套时间线本身就是很好的**一致性校验**——把「上传日 vs 大纲讲次」排成表，任何错位一眼可见。新课件到达时顺手更新 `课件上传时间线.md`。

## 十三、图表类课件要分两层记：事实层 + 推断层（立规，用户明确要求）★

**触发情形**：一份课件里**图表很多、却几乎不给解读**——这是老师**刻意留白**，意图是让学生**自己从图里读出信息**。此时的笔记若只抄图上数字，就漏掉了本讲真正的训练目标。

**硬性做法**：同一讲的笔记**必须分成两层，并逐条标明层属**：
1. **事实层**（如 EFGH5678 §9.11–9.12）：只记「**图上有什么**」——图表标题、系列、逐年数值。**这是课件内容，可以照引。**
2. **推断层**（如 EFGH5678 §9.21）：记「**我从图里读出了什么**」。**必须逐条标注为「我的推断，非课件内容」**，并在小节开头就声明，不能只在末尾提一句。

**推断层必须包含的四件东西**：
- **口径检查先行**：这些图往往来自不同报表、口径不统一。落笔前先问——**名目还是实质？组别有没有开口组？分母含不含某类人（如外佣）？序列有没有统计断点？** 这四条常常能直接推翻一个「看起来很明显」的结论。
- **证据强度分级**，逐条标注：**【图内推断】**（只用图上数字即可推出，可信度较高）／**【外部佐证后成立】**（需要课件没写的背景事实，须另行核实）／**【数据质量存疑】**（推断指向数据本身有口径问题，据此不该下结论）。
- **单独的「需外部资料才能证实」清单**：把那些依赖外部政策/文件的推断列成表，写明**缺什么证据**，明确标注**不要当结论直接用**。
- **贯穿性推断**：把散图连起来读出的整体判断（往往正是本讲论点）。

**使用提醒必须写进笔记**：事实层可照引；**推断层采用时必须说明是「基于课件的推断」**，课堂答题与写入报告时尤其如此。

**来源**：EFGH5678 第 6 讲（香港）33 张图表，实践约定要求「把推断也放进信息内，标注是你推断的，不是课件内容」。

## 十四、给老师的邮件要模仿用户语气（实践立规）★

> **触发**：任何写给老师的邮件（练习答复、请假、退课、退出活动、询问要求等）。提供两封**实寄**邮件截图，明确要求「以后类似任务要模仿其语气」。

**样本**：`.claude/skills/polyu-courseware-notes/references/邮件语气样本.md`（两封邮件逐字转录 ＋ 草稿与定稿的逐项差异）。**写新邮件前先读它。**

**硬规则**
1. **不道歉、不铺垫**。第一句直接给答案。删掉 `Apologies for the delay`、`Below is my response to…` 这类开场。
2. **第一人称判断句**：`I think the most effective one is …` / `I would want …` / `I might also need …`。不用 `the set likely to be …` 这种含蓄第三人称。
3. **每段用短标签句起头**：`Out of the 11 measures, I think …` / `The least effective is …` / `The data I need: …` / `As for policy implications, I think …`。结构靠标签，不靠过渡词。
4. **允许 `Because …` 起句**（他的习惯，两封都有）。
5. **列举用逗号串在句内**，不用项目符号、不加粗、不做小标题。
6. 需要引用课件/题目时**只留最短一句**原文加双引号，紧跟一句自己的评论；不复述题目背景。
7. **落款固定**：`Best regards,` → `[你的姓名]/ [English Name]` → 学号（必要时再加一行课程代码）。
8. **篇幅 150–200 词、3–4 段，不写总结段**。

**不要做的**：不要把他平实的短句润成学术腔、不要加「首先/其次」式排比、不要自行加礼节性寒暄。他的辨识度就是平实短句 ＋ 少量不完美的连接，改顺了反而像 AI 写的。

**与 §十一 的关系**：§十一「演讲稿要能念」只适用口头稿；邮件一律按本节。内容可以是 AI 给的，**语气必须是他的**。

## 十五、小组演讲作业：数据一致性优先于数据准确性（实践立规）★

> 用户原话：「这种演讲作业，**数据一致性比数据准确性更重要**。」来源：EFGH5678 组报告（11/12）第 2 节起草时，用户明确要求**先不要自行爬取 OECD 数据**，等组员的数据。

**行为规则**
1. **不抢先抓数**。小组报告的指标数据，**等组员提供**或先问「我们组统一用哪一组数」，不要自己去找一套更权威的塞进去——两节用两套数，评委会当场发现矛盾。
2. **一致性有两层，第二层更容易被忽略**：① **同一个数字**（同一指标全组只出现一个值）；② **同一口径**（净替代率 vs 毛替代率、相对贫困 vs 绝对贫困、等值家户收入 vs 人均、年份是否同为 2022/2023）。**口径不一致时，即使数字都对也会互相打脸。**
3. **分工**：把**结构、口径定义、论证链**备好，让任何一组数字都能直接插进去；组员报数时负责**核对交叉矛盾**（同一指标在两节出现两个值 → 立即提出，不擅自改）。
4. **发现数字与公认来源明显不符时**：提出并给出出处，**由组内决定改不改**；不要单方面修正别节的内容。

**配套**：为每次小组报告建一张「**数据口径登记表**」（指标｜定义／口径｜年份｜来源｜提供人｜已确认），组员报数时直接填，一致性由此机械保证，而不是靠记忆。

## 十六、判断「哪些作业已做完」必须按日期逐课核对（实践立规）★

> **触发**：用户说「已经做完的 pre／作业的文件都可以删了」。
> **本次教训**：曾只归档了「最近在忙的那门课」的一次展示，**漏掉另一门课已经讲完的报告**——报告日就写在那门课的 `README.md` 里，一查就有。

**错误做法**：只看**最近在忙的那一门课**。刚做完的东西占据注意力，会让人把「最近」当成「全部」。

**正确做法**

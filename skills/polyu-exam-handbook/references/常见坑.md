# 三个真实翻车案例

## 1. 目录页码全是 00

**现象**：图解版 PDF 第一页出现两份目录，第二份页码全是 `00`。

**原因**：md 里原本有一张给 Word 用的目录表（`| 章节 | 页码 |`），HTML 生成器把这张表也渲染了；同时生成器又会根据章节标题生成一份 `.toc`。两份叠在一起。

**修法**：生成 HTML 时**跳过 md 的目录表**，只用生成的 `.toc`（占位 `<span class="tpg" data-sec="N">`），渲染后回写真实页码。

## 2. 页脚章节整体错位一页

**现象**：第 10 页明明主要是 L6/L7 的内容，页脚却写 `§10 Lecture 9`。

**原因**：脚本里「章节起始页」存的是 `pymupdf` 的 **0-based 页码索引**，比较时用的却是 **1-based** 页码。

**修法**：统一 1-based（`st = index + 1`）；页脚标签取「`st < pno` 的最后一节 ＋ `st == pno` 的所有节」。

## 3. 出现 7% 填充的废页

**现象**：按「每节另起一页」排版后，有几页只有标题和一两行。

**原因**：无条件给每个 `##` 加 `break-before: page`，短章节被孤立。

**修法**：改成 60% 定律——只有**标题**落在页面 60% 以下才换页；表格用紧凑样式收尾；长段落允许跨页。

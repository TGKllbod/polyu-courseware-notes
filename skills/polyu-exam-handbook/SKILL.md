# 开卷考试手册（polyu-exam-handbook）

> 适用：**开卷、限时（2 小时左右）、题型为「若干单选 + 1 道论述」** 的课程考试。
> 核心判断：考场里只有两个动作——**找定位**（这题属于哪条线）与**找原句**（定义怎么写）。两种动作需要的排版相反，所以要做**两份同内容、不同载体**的文件。

## 一、三条硬规则

1. **一份内容、两种载体**：Word 详版 ＋ 图解版 PDF。图解版**只换呈现，不许删内容**（用户会拿两份对照）。
2. **定义引原句，不改写**：关键定义从课件 PDF 抽原文，**逐字引用＋标注课件页**。
3. **页码是算出来的**：目录页码、页脚页码都由「渲染后实测」回写，不许手填。

## 二、交付物清单

| 文件 | 读者动作 | 排版取向 |
| --- | --- | --- |
| `XX_开卷考试手册.docx` | 抄定义、写论述 | 连续排、目录带页码、页脚「页码/总页数」 |
| `XX_开卷手册_图解版.pdf` | 判题型、比关系 | 每讲开头一图、条目卡片化、页脚「本页章节＋页码」 |
| `XX_Quiz速查.docx`（可选） | 临出门看 5 分钟 | 一页：时间地点、必带、关键词→讲次 |

## 三、内容五件套（缺一不可）

1. **考试事实**：时间／考场／座位／题型分值／可带与禁带／评分口径——**全部来自录音或课件原话**，不写推测。
2. **概念速查**：术语 ｜ 英文定义 ｜ 中文 ｜ 讲次·人物 四列，字母序，约 40 条。
3. **逐讲要点**：核心命题 → 机制 → 对照表 → 关键批评 → **论述怎么用**。
4. **原文定义层**：引课件原句，标页（见 §四）。
5. **押题三层**：综合题（跨讲，最可能）→ 单讲题（每讲至少一道）→ 万能骨架。

## 四、原文定义怎么写

用户原话：「关键的定义的解释需要完整，最好完整放原文，不需要压缩重新解释一遍」。

```markdown
**Verbatim definitions ｜ 原文定义（课件原句）**
> "Legibility: capable of being discovered or understood" (L1, p.12)
> "SAPs: 'a comprehensive restructuring of production priorities and government programs in a debtor country'" (L4, p.33)
```

- **每条独立成块**：不要在一个 `>` 后接多行（解析器会合并成一段）；
- 短定义 → 左竖线样式；长段（>220 字符）→ 方框样式；
- **为什么**：评分看术语准不准。`No debit side`、`chemical treadmill`、`command posts in the world economy` 这类措辞，抄原句比意译更像读过课件。

## 五、四条流水线

```bash
# 1) Word 详版
python3 scripts/md_to_docx.py 开卷考试手册.md          # 见 polyu-courseware-notes skill
python3 scripts/paginate_docx.py 开卷考试手册.docx --break 1,14,15

# 2) 图解版 HTML（--flows 传每讲流程图）
python3 scripts/handbook_html.py 开卷考试手册.md 图解版.html --flows flows.json

# 3) PDF + 目录页码 + 页脚
python3 scripts/deck_pdf_pageno.py render 图解版.html 图解版.pdf
python3 scripts/deck_pdf_pageno.py toc    图解版.html 图解版.pdf 开卷考试手册.md
python3 scripts/deck_pdf_pageno.py stamp  图解版.pdf 开卷考试手册.md

# 4) 按 60% 定律调分页（迭代到「无低起点章节」）
python3 scripts/deck_pdf_pageno.py rule60 图解版.html 图解版.pdf 开卷考试手册.md
```

`flows.json` 形如：

```json
{"3": [["Society","complex, contextual"],["State simplifies","census · maps"],
       ["Becomes legible","readable from centre"],["Governed","taxed, engineered"]]}
```

## 六、页码与页脚的三个机制

| 位置 | 机制 | 常见错误 |
| --- | --- | --- |
| Word 目录 | 渲染 PDF → 定位标题 → 回写 md 表格 → 重建 → 复核 | 章节挪页后忘了重算，写成 `None`/`00` |
| PDF 目录 | HTML 留 `<span class="tpg" data-sec="N">--</span>`，渲染后按实测回写，**迭代到稳定** | md 里那张目录表被同时渲染 → 出现两份目录，其中一份是 `00` |
| 页脚 | PyMuPDF 盖章：左「本页所含章节」、右「页码 / 总页数」 | Chrome 打印**不出页码**；0-based/1-based 混用导致整体错位一页 |

**页脚双标签规则**：一页里既有上一节的尾巴、又有下一节的开头时，写 `§9 … · §10 …`。

## 七、60% 分页定律

> 用户原话：「页面可以空一点但不要 80% 都是空的；准备切换到新章节且页面已经填了超过 60% 时可以适当换页」。

- 只有**章节标题**触发规则，**段落与表格不触发**；
- `rule60` 记录 `.force_breaks` → 重新生成 HTML → 再测，实践 **2–3 轮收敛**；
- 配套约束：≤12 行表格整表不拆；>30 行用紧凑样式（字号 −0.4pt、内边距 −0.5mm）；长段落（>400 字）允许跨页，只保孤行控制；
- **验收**：平均填充 ≥80%，最空页 ≥50%，无空白 >45% 的页。

## 八、押题怎么写（单题考试）

只有一道 essay 时，**综合题概率最高**——只问一讲的题写不满 90 分钟。

| 层 | 数量 | 每题给什么 |
| --- | --- | --- |
| **综合题** | 5 道 | 小问 (a)–(d) → 六步提纲（带分钟）→ 标志性证据 → **失分点** |
| **单讲题** | 每讲 1 道 | 题目 / 考点 / **三步答法** |
| **详版范文** | 3–6 篇 | 约 500 词英文范文 ＋ 中文段落说明 ＋ 得分点 |

**万能开头段**：第一句给**机制**（评分点），第二句承诺**比较**，第三句先认**局限**。

## 九、覆盖率自检（交付前必做）

1. pdfplumber **抽取全部课件文字**；
2. 取每讲高频专名 → 与手册正文比对，列出「课件有、手册无」；
3. **人工判定**：知识缺口 vs 标题词/事务信息（`MASPSD`、`Boarding`、`Submit` 一律不算）；
4. 补齐后**再跑一遍**，直到只剩英式/美式拼写差异。

## 十、交付前清单

- [ ] 目录页码与正文**逐条**一致（脚本自动比对）
- [ ] 每页有页码，形态 `12 / 31`
- [ ] 页脚章节标签与实际内容相符（尤其一节跨两页）
- [ ] 最空页 ≥50%，无空白 >45% 的页
- [ ] 关键定义是**课件原句**，带课件页
- [ ] 每讲至少一道题；综合题 ≥3 道
- [ ] 覆盖率自检已跑
- [ ] 事实核对：年份、人数、比例、机构名都能在课件或录音找到出处
